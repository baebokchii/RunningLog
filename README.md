# 내 러닝 기록 대시보드

애플 피트니스(애플워치)에 쌓인 내 러닝 기록으로 "나는 예전에 비해 얼마나 더 잘 뛰는가"를 보여주는 대시보드 프로젝트입니다.

**대시보드 보기:** [Tableau Public – Running Log Dashboard](https://public.tableau.com/views/RunningLogDashboard/RunningLog)

[![러닝 로그 대시보드](docs/RunningLog.png)](https://public.tableau.com/views/RunningLogDashboard/RunningLog)

## 주요 발견 (2022-06 ~ 2026-10, 러닝 99회)

- **총 251.1km**를 달렸고, 기록 기간 53개월 중 30개월 동안 뛰었습니다.
- **2025년 6월부터 거의 매달** 뛰었습니다. 그 뒤로 쉰 달은 2025년 12월, 2026년 6월 두 번뿐입니다.
- **최근 5회 페이스가 전체보다 24초 빠릅니다.** 최근 5회 6'31", 전체 6'55"입니다. (총 시간 ÷ 총 거리 기준)

## 대시보드로 답할 질문

1. **꾸준함**: 언제 많이 뛰었고 언제 쉬었나? 월별 거리는 어떻게 늘어났나?
2. **러닝 실력 향상**: 심박 거리, 페이스 추세로 보아 얼마나 실력이 늘었나?

## 데이터

- 출처
  - ~2026-10-20: 아이폰 건강 앱 "모든 건강 데이터 내보내기" (애플워치 + 나이키 런클럽 기록). 한 번 구글 시트에 올린 뒤로는 시트가 원본입니다.
  - 2026-10-22~: 러닝이 끝난 뒤 보내는 피트니스 앱 운동 화면 스크린샷 (맥에서 글자를 읽어 기록으로 바꿈)
- 원본 건강 데이터, 러닝 시작 시각, 경로(GPS)는 개인정보라 저장소와 대시보드에 올리지 않습니다.

### 정리 기준

| 기준 | 이유 |
|---|---|
| 1km당 12분 초과 기록 제외 | 걷기나 중간에 멈춘 기록이 섞여 있음 |
| 거리 0.5km 미만이거나 거리·시간이 없는 기록 제외 | 기록 오류 |
| 두 앱에 중복 기록된 러닝은 애플워치 기록만 사용 (내보내기 시절 기록) | 애플워치 기록에만 심박이 있음 |

아침/저녁 비교와 기온 분석은 뺐습니다. 러닝 대부분이 저녁이고, 기온이 기록된 실외 러닝이 적어서입니다.

## 업데이트 구조

```
피트니스 앱 운동 화면 캡처 → 공유 → '러닝 기록 보내기' 단축어가 iCloud Drive의 data/에 저장
  → launchd가 data/ 변화를 감지해 src/update.py 실행
  → 맥 내장 Vision으로 글자 읽기 → 정리
  → 구글 시트에 없는 기록ID만 추가 (월별 탭 재계산) → 전부 올라간 것을 확인하면 스크린샷 삭제
  → Tableau Public이 구글 시트를 하루 1번 동기화
```

### 업데이트 방식 개선 (2026-10)

| | 이전: 건강 데이터 전체 내보내기 | 지금: 피트니스 화면 스크린샷 |
|---|---|---|
| 직접 하는 일 | 건강 앱에서 전체 내보내기 → 파일 생성 대기 → 맥에서 AirDrop 받기 | 운동 화면 캡처 → 공유 → '러닝 기록 보내기' |
| 걸리는 시간 | 약 3분 | 약 10초 (**약 94% 단축**) |
| 데이터가 쌓이면 | 내보낼 파일이 커져 점점 느려짐 | 러닝 1회 화면만 보내므로 그대로 |
| 맥 조작 | AirDrop을 받으려면 맥을 켜서 확인 | 필요 없음 (iCloud로 받아 자동 처리) |

### 스크린샷 읽기

"모든 건강 데이터 내보내기"는 데이터가 쌓일수록 오래 걸려서, 방금 뛴 러닝의 피트니스 앱 화면만 보냅니다. 맥에서는 `src/screenshot_runs.py`가 `tools/ocr.swift`(맥 내장 Vision, 인터넷 연결 없음)로 글자를 읽어 아래 값을 `data/runs.csv`에 한 줄로 추가합니다. `data/runs_clean.csv`와 `data/monthly.csv`는 `runs.csv` 전체로 다시 만듭니다.

| 화면 | 값 |
|---|---|
| 실외 달리기 / 실내 달리기 | 장소 |
| 2026년 10월 22일 20:14 ~ 20:31 | 날짜, 시작 시각 (기록ID에만 씀) |
| 운동 시간 0:17:21 | 시간 (일시정지 제외) |
| 거리 2.49KM | 거리 |
| 평균 페이스 6'57"/KM | 페이스 |
| 평균 심박수 170BPM | 평균심박 |

- 피트니스 앱 값을 그대로 쓰므로 대시보드 값이 애플 기록과 같습니다. 기록ID도 예전 기록과 같은 방식(시작 시각 + 기기)으로 만듭니다.
- 글자를 잘못 읽었을 수 있어서, 운동 시간 ÷ 거리가 화면 페이스와 맞을 때만 받아들입니다. 맞지 않거나 값을 찾지 못하면 `data/failed/`로 옮기고 알림을 띄웁니다.
- 스크린샷에는 위치와 지도가 있어 처리 후 바로 지우고, 저장소에도 올리지 않습니다.
- 단축어 파일에는 iCloud 폴더 정보가 들어 있어 저장소에 넣지 않았습니다.

심박이 없던 예전 나이키 런클럽 기록은 시트에 평균심박을 직접 채웠습니다. 시트에 이미 있는 기록은 업로드 때 덮어쓰지 않기 때문에 직접 채운 값도 그대로 남습니다.

| 파일 | 역할 |
|---|---|
| `src/screenshot_runs.py` | 피트니스 스크린샷 → `data/runs.csv`에 추가 |
| `tools/ocr.swift` | 이미지 글자 읽기 (처음 쓸 때 `~/Library/Caches/RunningLog/ocr`로 컴파일) |
| `src/clean_runs.py` | 정리 + 기록ID 부여 → `data/runs_clean.csv`, `data/monthly.csv` |
| `src/upload_sheet.py` | 시트에 없는 기록만 업로드하고, 전부 올라갔는지 확인 |
| `src/update.py` | 위 단계 실행 후 스크린샷 삭제, 결과 알림 |
| `src/common.py` | 공통 경로, 기록ID, 시트 연결 함수 |
| `apps_script/Code.gs` | 구글 시트 쪽 웹 앱: 중복 거르기, 월별 요약 |
| `launchd/…plist` | `data/` 감시 설정 (개인정보로 업로드에서는 제외) |

직접 실행: `python src/update.py`

## 도구

- Python(pandas): 데이터 정리, 구글 시트 업로드
- Swift + macOS Vision: 스크린샷 글자 읽기 (인터넷 연결 없이 맥 안에서 처리)
- iOS 단축어, iCloud Drive, launchd: 아이폰에서 보내고 맥에서 자동 처리
- Google Apps Script + 구글 시트: 기록 저장, 월별 요약
- Tableau Public: 대시보드
